# 分享、作者信息与编辑权限

导出小组件时，可以附上作者资料和小组件简介。需要限制接收者的编辑或转发能力时，再开启“分享保护”。

## 作者与小组件信息

导出页支持填写：

- 作者名称
- 主页或社交链接
- 作者简介
- 小组件简介

输入内容不符合要求时，提示会直接显示在对应输入框下方；修正后即可继续导出。

作者资料是署名信息，不代表实名或官方认证。受保护分享可以验证署名和权限信息没有被普通导入流程修改，但不能证明作者的真实身份。

完成设置并点击“导出”后，AWidget 会把 `.omni` 文件交给 iOS 系统分享面板。可以从分享面板选择“存储到文件”、AirDrop 或其他支持文件分享的 App，不再预先要求选择保存路径。

投稿小组件时也会使用相同的作者、简介和分享保护设置。后台审核页会直接读取 `.omni` v3 清单中的作者与权限信息；审核通过后，“发现”页面提供的包会保留这些设置。

每个新版 `.omni` v3 文件的外层还会包含一个 `preview.png` 封面。封面的文件名、PNG 尺寸和 SHA-256 会写入清单并参与完整性校验。投稿时 App 只上传 `.omni` 文件，后台验证后直接提取这个封面，不再单独接收一份预览图。

:::warning 封面是公开内容
即使开启分享保护，外层封面也不会加密，以便文件接收方和投稿后台在解密组件内容前展示预览。不要让封面包含账号、地址或其他敏感信息。
:::

## 在 Home 查看信息

在 Home 点击一个小组件时，会先打开信息页，而不是直接进入编辑器。信息页会显示：

- 小组件预览、类型、简介和更新时间
- 作者名称、简介和主页链接
- 是否来自受保护分享
- 组件编辑、代码访问、复制和再次导出权限

作者信息显示在常用操作按钮上方。信息页提供“编辑”“复制”“导出”“重命名”和“删除”按钮；未开启分享保护的小组件还会显示“投稿”。删除前会再次确认，投稿成功后会显示 HUD 提示。需要密码的编辑权限会在“编辑权限”卡片中显示“输入密码解锁编辑权限”，密码验证统一在这里完成。

Home 列表左滑只保留删除，并需要再次确认。网格模式不再提供长按菜单，编辑、复制、导出、重命名和投稿都从信息页进入。

如果“组件编辑”需要密码但尚未解锁，或被作者禁止，点击“编辑”仍会进入正常的预览编辑页面，但底部组件编辑器保持关闭，也不会显示组件列表、布局属性或代码入口。有用户配置时，App 会自动弹出作者预留的城市、颜色、账号等设置；保存后设置页关闭，并立即在预览中显示最新效果。没有用户配置时则直接显示完整预览。解锁成功后，再次进入即可使用完整编辑器。

从文件、Share Extension 接收 `.omni`，或在“发现”页面下载小组件后，也会先打开同一个信息页。确认作者、简介和权限后，再点击“编辑”进入编辑器。

## 无保护分享

“分享保护”默认关闭。关闭时仍使用新版 `.omni` v3 容器，但内容不加密：

- 导出不要求联网。
- 接收者可以正常编辑、复制和再次导出。
- 作者资料会随文件一起导出。
- 文件包含导出 App 的 build 号。

:::warning 开发阶段格式
新版 AWidget 只会导出带外层封面的 `.omni` v3，但仍允许从文件或 Share Extension 恢复旧 App 导出的目录包。旧包没有作者签名、密码权限或 App build 限制，导入后按 legacy 小组件处理并默认完整可编辑。开发阶段的受保护 v2 包，以及不含外层封面的早期 v3 包，不继续兼容；“发现”页面的旧资源还会先校验后台文件哈希。
:::

## App build 限制

每次导出都会把当前 `CFBundleVersion` 写入 `manifest.json` 的 `appBuild` 字段。

- 当前 App build 大于或等于包的 `appBuild` 时，可以继续导入。
- 包的 `appBuild` 高于当前 App 时，AWidget 会拒绝导入并提示先更新 App。
- 这个值是 App build 号，不是面向用户显示的版本号。

## 受保护分享

开启“分享保护”后，可以分别设置以下权限：

| 权限 | 控制内容 |
| --- | --- |
| 作者信息 | 修改作者名称、链接和简介 |
| 组件编辑 | 修改布局、组件属性、资源和小组件简介 |
| 查看与编辑代码 | 查看或修改 JavaScript 与 Markup 源码 |
| 复制组件 | 在 App 内复制该组件 |
| 再次导出 | 生成新的分享文件 |

每项权限都可以设为“允许”“密码”或“禁止”。选择“密码”时，一个密码会解锁该分享包里所有需要密码的权限。未获得代码权限时，源码不会显示。

运行设置、本地名称修改和删除始终可用。例如，作者锁定布局和代码后，接收者仍然可以填写城市、颜色或账号等设置项。

MCP 本地服务也遵守相同权限。未解锁时，`get_widget` 不返回受保护的源码或布局，`update_widget` 不能修改代码、Markup、组件布局或用户配置定义，`run_js` 也不能借用受保护组件 ID 执行代码。新建组件、语法校验和本地重命名不受这些限制。

:::warning 首次导入必须联网
受保护 `.omni` 文件的首次导入需要连接 Omni 后台，以验证 App 和文件、检查导入配额并获取解密授权。成功导入后，小组件可以离线运行；密码成功验证一次后，当前 App 安装实例也可以离线编辑已解锁内容。
:::

## 限制导入数量

可以设置一个分享包最多授权多少个 App 安装实例。

- 同一台设备上的同一个 App 安装实例重复导入，不会重复占用名额。
- 卸载重装、换机或 App Attest 密钥失效后，通常会被视为新的安装实例。
- 达到上限后，新的安装实例不能再首次导入；已经授权的实例不受影响。

这个数量表示经过 App Attest 验证的 App 安装实例，不等同于绝对唯一的物理设备数量。

## 安全边界

受保护分享会加密 `.omni` 中的组件内容，并让后台验证文件哈希、权限和 App 实例。`manifest.json` 和 `preview.png` 保持公开，布局、资源与源码位于加密载荷中。分享保护后台只保存文件密钥和授权信息；只有主动投稿时，投稿后台才会保存收到的 `.omni` 和从中提取的公开封面。

导入成功后，内容仍按 AWidget 现有格式保存在 iOS App 沙箱中。因此这项功能不能保证阻止越狱设备、运行时分析，或已经获得授权的接收者提取明文内容。

撤销一个分享包只能阻止新的导入和解锁，不能远程收回已经离线授权的组件。
